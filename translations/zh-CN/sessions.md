# 会话与上下文

Pi 将对话保存为会话。会话的活动分支为下一次模型请求提供对话历史。通过会话命令，你可以继续工作、探索其他分支，或减少发送给模型的历史内容。

## 继续或切换会话

除非使用 `--no-session` 启动，否则 Pi 会自动保存会话。

```bash
pi --continue
pi --resume
```

`--continue` 打开当前工作目录下最近的会话。`--resume` 打开会话选择器。交互模式下，`/resume` 打开相同的选择器，`/new` 则开始新会话。

使用 `/name` 或 `--name` 设置便于辨识的会话名称。运行 `/session`，确认当前会话文件、ID、消息数量、token 用量和费用。

会话选择器支持搜索、重命名和删除会话，也可以显示路径、更改排序，并将结果限制为已命名会话。相关快捷键请参阅[按键绑定](keybindings.md#sessions)。

## 选择分支方式

Pi 以树形结构存储条目，因此返回较早位置，不会擦除你离开的分支。

| 操作 | 结果 | 适用场景 |
|---|---|---|
| `/tree` | 在当前会话文件内移动 | 相关的替代方案应保存在一起 |
| `/fork` | 从较早的用户消息创建新会话 | 替代方案应成为独立工作 |
| `/clone` | 将活动分支复制到新会话 | 希望单独复制当前状态 |

在 `/tree` 中选择用户消息，可以将文本放回编辑器。编辑并提交后，就会创建另一个分支。选择助手响应或其他条目，则从该条目之后继续，编辑器保持空白。

离开分支时，Pi 可以为其生成摘要，并将摘要附加到你进入的分支。这能保留已离开路径中的相关工作，而不必包含其中的每条消息。

持久化树结构与条目类型请参阅[会话格式](session-format.md)。

## 管理对话上下文

模型收到的是活动分支，而不是会话文件中的全部分支。Pi 将这段历史与系统提示、发现的上下文文件、可用工具及已加载的技能描述组合起来。[Pi 的工作原理](how-pi-works.md#context)介绍了这些输入的组装方式。

底栏显示当前上下文使用量。当活动上下文接近模型限制时，Pi 通常会自动压缩较旧的历史。压缩会添加摘要并保留近期消息，不会删除原始会话条目。

运行 `/compact` 可以手动压缩。如果摘要需要保留特定主题或决策，可以附加指令。通过[设置](settings.md#compaction)配置自动压缩和保留的历史内容。

如果提供商不可用，或无法接受摘要请求，压缩可能失败。解决提供商的问题后，再次运行 `/compact`。禁用自动压缩并不会禁用手动命令。

关于阈值、保留边界、分支摘要行为及扩展钩子，请参阅[上下文压缩参考](compaction.md)。

## 控制会话存储

默认情况下，Pi 将会话保存在 `~/.pi/agent/sessions/` 下，并按工作目录分组。可以使用 `--session-dir`、`PI_CODING_AGENT_SESSION_DIR` 或 `sessionDir` 设置选择其他位置。CLI 选项的优先级最高。

使用 `--no-session` 进行临时运行。Pi 退出后，临时会话无法恢复。

已经知道会话路径或 ID 时，使用 `--session`。要在进入交互模式前，根据已有会话创建新会话，使用 `--fork`。

## 导出或分享会话

使用 `/export` 将当前会话写为 HTML 或 JSONL。使用 `/share` 上传会话并获取查看链接。默认情况下，配置了 Radius 身份验证时，Pi 使用 Radius 产物；否则使用私密 GitHub gist。将 [`sessionShareDestination`](settings.md#sessions-and-context) 设置为 `gist` 或 `radius`，可强制选择其中一个目标。

导出或分享会话前，请先检查内容，其中可能包含提示、模型响应、工具参数、命令输出、文件内容和扩展消息。

## 报告问题

运行 `/bug [description]`，为 Pi 开发者准备私密问题报告。你可以包含会话记录、不包含会话记录，或让当前模型总结问题。请检查所有会话记录或生成的摘要，因为其中可能含有敏感对话数据。

报告包含环境与提供商配置，但不包含凭据值，同时附带记录的错误诊断信息。你可以通过 `radius.pi.dev` 上传，也可以将同一报告导出为 zip，自行检查和分享。上传不要求登录；Radius 身份验证会将报告关联到你的账号，方便开发者跟进。上传失败时，Pi 会提供导出 zip 的选项。
