# Pi 的工作原理

Pi 协调模型请求、工具执行、上下文组装和会话存储。会话是 Pi 对一段对话的记录，包含消息、工具调用及结果、模型切换、上下文压缩和其他事件。

会话中的消息与事件组成一棵树，树中的每条路径都是一个分支。以当前条目结尾的分支就是活动分支，为下一次模型请求提供历史记录。

## 智能体循环

提交的消息会添加到活动分支。Pi 根据系统提示、活动分支、可用工具和模型设置构建模型请求，再通过选定的提供商发送。

提供商以流式方式返回助手响应，其中可能包含文本和工具调用。Pi 记录响应、执行各个工具调用，并记录结果，至此完成一轮。如果工具结果或排队消息需要再次请求模型，Pi 就开始下一轮；否则，本次运行结束。

引导消息在当前助手轮次结束后进入对话；后续消息则在智能体完成待处理工作后进入。中止操作会停止当前运行，并将排队消息放回编辑器。

## 上下文

活动分支提供对话历史。Pi 将其中的会话条目转换为模型兼容的用户消息、助手消息和工具结果消息。

Pi 根据基础指令和发现的上下文文件构建系统提示。请求还包含工具定义和技能描述。

完整的技能指令按需加载。扩展可以添加指令，也可以转换上下文。

提示模板会在编辑器输入成为用户消息之前将其展开。选中的文件、图像、粘贴的文本和 shell 输出，都可以成为消息内容。

## 会话

持久化会话保存为 JSONL 文件。树中的每个条目都有 ID，并引用其父条目。当前条目决定活动分支。

从较早条目继续，会在同一文件中创建另一个分支。派生和克隆操作会将选定历史复制到新的会话文件。

模型上下文由活动分支重建。上下文压缩会插入摘要条目，在后续模型请求中替代较旧的消息；原始条目仍保留在会话树中。

## 接口

交互模式将会话和智能体事件呈现在终端中。Print 模式运行提示并输出最终响应。JSON 模式将智能体事件输出为 JSONL。

RPC 模式从 stdin 接收 JSONL 命令，并向 stdout 写入响应和事件。TypeScript SDK 则在进程内部创建和控制智能体会话。

所有接口都使用相同的智能体与会话机制。

## 扩展与资源

扩展是加载到 Pi 进程中的 TypeScript 模块。其工厂函数可以注册工具、命令、快捷键、提供商、事件处理器、渲染器和终端 UI。

技能提供按需加载的指令和辅助文件。提示模板提供可复用的消息文本。主题提供终端配色。Pi 包通过 npm 或 git 分发这些资源。

## 信任与权限

Pi 会在加载项目设置和资源之前，先确定项目信任状态。在完成信任决策和项目资源加载后，Pi 再加载上下文文件。已启用的工具使用 Pi 进程的操作系统权限，扩展则在该进程内部执行。
